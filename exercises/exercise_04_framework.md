# 练习 04：交付一次业务需求变更

毕业目标：能够接手需求、评估影响、实现并验证变更，不以重新包装一套 Client 或堆目录作为主要成果。

## 新需求：任务归档

在现有服务上增加 status=archived，规则如下：

- 新建任务仍为 open；允许 open↔done、done→archived。
- open→archived 和 archived→其他状态返回 409，字段均不得被部分更新。
- archived 任务可查询和删除，不允许修改 title，违规返回 409。
- GET `/tasks` 默认不返回 archived；`?include_archived=true` 返回全部自己的任务，false 等同默认，其他值返回 400。
- 现有身份认证、越权和数据隔离规则继续生效。

这是练习的目标需求，当前靶场尚未实现，不应在完成前把以上行为当作现有功能。

## 交付顺序

1. 新建 `docs/change_archive.md`，用一页说明需求、状态转换、兼容性、风险、数据迁移和测试范围。
2. 更新接口契约与测试设计。用参数化覆盖允许/禁止的状态转换；补列表过滤和原子性断言。
3. 先写能暴露差异的测试，再修改服务及 Schema，避免把预期改成实现当前输出。
4. 增加回归，保留旧有 open/done、权限与清理能力。禁止依赖测试执行顺序。
5. 本地、并行与 CI 验证；归档报告和实际依赖版本。
6. 按 `docs/DEBUGGING.md` 写一份开发中发现的缺陷报告，说明定位过程与修复验证。

验收按 `docs/DELIVERY.md`。评审时演示一条正常链路、一条被拒绝的转换、一条越权尝试，以及一个故意注入的缺陷如何被发现。

框架抽象选做：只有测试出现重复登录、重复业务请求或重复数据准备时，提出业务服务层/工厂的抽取方案，并用使用示例说明收益。不要为了简历而复制现有 core 再改名。

## 最终联合交付

把练习 05—07 的 SQL、Linux、JMeter 成果并入作品包：用 SQL 证明归档状态落库及失败无部分写入，在 Linux 回归，用 JMeter 为变更后的查询行为补断言。按学习成果章节自测，再按简历章节整理个人贡献，禁止把教程原有代码全部写成独立开发。
