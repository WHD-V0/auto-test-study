# 练习 04：设计你自己的接口测试框架（毕业项目）

> 目标：把前 3 周所学内化成"能讲清楚、能落地"的框架设计能力。
> 这就是你简历上"独立搭建接口自动化测试框架"的底气。
> 形式：**先写设计文档，再写代码**——顺序不能反，企业里就是这么干的。

## 阶段一：设计文档（先做，1 页以内）

新建 `docs/framework_design.md`，回答以下问题：

1. **分层设计**：你的框架分几层？每层职责是什么？（参考本项目：config / core / data / tests）
2. **用例组织**：按什么维度组织测试目录？业务模块还是接口类型？
3. **数据管理**：配置放哪？测试数据放哪？密码 token 怎么处理？
4. **断言策略**：什么时候用 Schema，什么时候手写业务断言？
5. **失败排查**：日志怎么打？报告用什么？重试策略是什么、有什么副作用？

## 阶段二：最小可用框架（核心）

在项目根目录新建 `myframework/`，要求：

1. **不用本项目 core/ 的代码**，自己实现一个 `Client` 类：
   - 统一 request 入口（日志 + 状态码校验 + 异常包装）
   - 支持 token 自动携带
2. 写至少 **8 个测试用例** 覆盖：查询、创建、更新、删除、404、鉴权、数据驱动、Schema 校验
3. 支持 `TEST_ENV` 环境变量切换两套配置
4. 跑 `pytest myframework_tests/ -v` 全绿

## 阶段三：工程化加分项（选做，面试亮点）

- [ ] `pytest --html` 生成报告，且报告里有用例描述
- [ ] `pytest -n auto` 并行执行不互相干扰（注意数据隔离）
- [ ] GitHub Actions：push 自动跑测试
- [ ] 失败用例自动截图/保存响应体到 `reports/`（hook: `pytest_runtest_makereport`，可让 AI 陪你写）

## 验收标准

- [ ] 设计文档每个问题都有明确答案和理由（"因为别的项目也这样"不算理由）
- [ ] 能对着代码给面试官讲 10 分钟框架设计
- [ ] 别人 clone 你的框架后，改一个配置文件就能跑起来
