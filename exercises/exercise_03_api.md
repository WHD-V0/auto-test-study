# 练习 03：完成可复现的业务测试

每天怎么做：先按 [阶段二](../docs/daily/02-http-design.md) 完成用例设计和手工验证，再按 [阶段三](../docs/daily/03-workflow.md) 实现独立、可清理的业务测试；每一天都有完成判定。

靶场改为本项目本地任务 API，不依赖 Reqres 或其他外网服务。先读 `docs/API_CONTRACT.md` 和 `docs/TEST_DESIGN.md`。预计一个阶段完成，不要求一个下午写完。

## 先设计，再实现

1. 写至少 12 条用例：需求编号、风险、前置、输入、预期状态、业务断言、清理方式。
2. 标明哪些已经由样例覆盖，哪些是你新增的，至少新增 6 条有独立风险意义的测试。
3. 缺少需求的地方先写出问题，不根据当前实现自动生成预期。

## 实现任务

在 `tests/workflow/test_tasks_extended.py` 编写测试，复用该目录 conftest 的服务、登录客户端和资源工厂。

- 创建 → 用返回 ID 查询 → 更新 → 再查 → 删除 → 404，所有步骤针对同一资源。
- Alice/Bob 权限矩阵：读、写、删和列表均验证，不只看请求是否带 token。
- 长度 1/80/81、空白归一化、错误类型、非法 JSON、未知字段保护。
- PUT 同时包含合法 title 和非法 status 时，断言数据库未部分更新。
- 找出服务尚未覆盖的行为，标记为“待需求确认”，而不是擅自约定。

## 持久化扩展

手动启动服务，创建任务后停止并用同一路径重启。重新登录，验证任务仍在，旧 token 失效。记录步骤，再考虑用临时数据库和服务器生命周期将其自动化。

## 验收

单独运行、连续运行两次、`-n 2` 均通过；不依赖之前测试创建数据；断言中途失败也清理已创建资源；204 使用原始响应；Schema 与业务断言都存在。故意去掉服务端权限判断后至少一个测试失败。

公共 API 迁移为选做：先核对当前官方文档、API key、持久化语义和使用限制。不能把返回 token 或原样回显提交值当成服务端真正验证权限、保存数据的证据。
