# 项目交付验收

作品应能让另一位同事复现，而不仅是作者电脑上显示通过。

## 必须交付

- 需求/契约与风险：说明测试目标、授权环境、优先级和未覆盖范围。
- 用例设计：包含正常、边界、异常、鉴权、越权、数据副作用，并能对应自动化测试。
- 测试代码：同一资源完成 CRUD，函数之间无顺序依赖，失败时也清理已创建资源。
- 环境说明：Python 版本、依赖安装、默认回归和外网测试分开运行的命令。
- 执行证据：本地回归、两个 worker 并行回归、一次成功和一次故意失败的 CI，HTML/JUnit 与安装版本。
- 缺陷报告：至少一处真实或主动注入的缺陷，有预期、实际、影响、最短复现和修复验证。

## 本地检查命令

以下 `python` 指当前虚拟环境解释器，Windows 建议写全 `.venv\Scripts\python.exe`。

```text
python -m pytest
python -m pytest tests/workflow
python -m pytest -n 2
python -m pytest --html=reports/report.html --self-contained-html --junitxml=reports/junit.xml
```

任何失败都保留非零退出码，CI 的 artifact 上传使用 always 条件，但测试步骤不设 continue-on-error。不要把公共网络可用性作为业务回归的隐含条件。版本范围不等于锁文件：CI 归档 pip freeze 便于复现，正式项目维护依赖锁及升级验证。

## 评审评分（100 分）

| 维度 | 分值 | 达标证据 |
|---|---|---|
| 用例与风险设计 | 30 | 解释场景选择，覆盖边界/权限/副作用 |
| 业务验证 | 25 | 持久化闭环、失败无副作用，不只检查状态码 |
| 稳定性与隔离 | 20 | 独立、可重复、可并行、清理失败可见 |
| 故障定位 | 15 | 最小复现、证据、根因、回归 |
| 可交付性 | 10 | README、CI、报告、版本与限制说明 |

缺少越权校验、依赖执行顺序或失败被重试掩盖时，不能用高用例数量补分。HTTP 标准库靶场使用演示鉴权，不是生产服务；性能、并发事务、登录安全与数据库迁移需在实际项目单独设计。

## SQL / Linux / JMeter 与求职材料补充验收

- SQL：独立查询、关联/聚合/NULL 与事务实验；参数绑定的只读落库断言；说明 SQLite 与 MySQL 边界。
- Linux：真实 Linux/WSL 回归记录；进程、端口、HTTP 和日志的排障证据；失败退出码能传递。
- JMeter：参数化/关联/断言的 JMX，JTL 样本数量与成功状态校验，对照报告和清理记录。
- 学习成果：按 [能力验收](LEARNING_OUTCOMES.md) 完成一次综合交付。
- 简历：按 [简历与面试](RESUME_INTERVIEW.md) 标注个人项目、复用与新增范围；数量和性能结果均可追溯。

普通 pytest CI 验证功能与配套工具，不自动执行 JMeter 压测。Linux 脚本应在 Ubuntu job 执行，性能实验另行记录机器、负载和业务预期。
