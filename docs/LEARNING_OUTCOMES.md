# 学完后，你能做什么

这是教程最后的能力验收，不是“看完即掌握”的清单。先完成九阶段作业，能脱离范例独立重做，再按自己的证据评估。随后阅读 [简历与面试](RESUME_INTERVIEW.md)。

## 1. 能力与证据

| 能力 | 完成后能独立做的事 | 必须拿得出的证据 |
|---|---|---|
| 测试分析 | 从接口契约推导正常、异常、边界、权限和副作用场景 | 有需求编号、优先级和预期依据的用例表 |
| Python / pytest | 编写断言、异常测试、fixture、参数化和 Mock | 自己新增的测试；故意改坏实现能检出 |
| 接口自动化 | 登录关联、同一 ID 的 CRUD、结构与业务断言 | 不访问公共网络即可重复运行的用例 |
| SQL | 条件、关联、聚合、NULL、事务和参数化查询，补充落库核对 | 练习 SQL、结果解释、只读数据库断言 |
| Linux / Bash | 在 Linux 运行回归，查进程/端口/日志，保留失败退出码 | Linux/WSL 执行记录及至少一次排障记录 |
| 工程化 | 隔离测试数据、失败清理、并行运行、CI 与报告归档 | 自己仓库的 CI 链接、HTML/JUnit 和版本记录 |
| JMeter | 参数化、token/ID 关联、断言、非 GUI 执行和基础指标分析 | 自己运行的 JMX/JTL、检查器结果、对照报告 |
| 故障定位 | 分清测试、环境、客户端和服务端原因 | 最短复现、证据、修复验证与回归范围 |
| 需求交付 | 理解变更、评估风险、补测试并说明取舍 | 归档需求作业、代码差异与评审说明 |

SQL 和 Linux 是接口测试岗位的常见基础；JMeter 是常见性能测试工具，但不同公司的工具链会不同。学习目标是把相应问题解决清楚，而不是把所有工具都写成“精通”。

## 2. 最终综合考核

给自己一个没看过答案的新需求，用 2—3 天完成小型交付：

1. 写清接口行为与风险，列出至少 12 条有区别的用例。
2. 自动化实现最高风险的场景，覆盖鉴权、越权、数据变化与失败不改变数据。
3. 选择一个需要查库的场景，用参数绑定做 SQL 核对，说明为什么仅看返回值不够。
4. 在 Linux/WSL 执行，处理一次环境问题，保留日志、命令和退出码。
5. 接入自己的 CI，证明测试失败不会被重试、tee 或忽略退出码掩盖。
6. 用 JMeter 做一次先正确性、后低负载对照的实验，检查样本数和断言，明确结论边界。
7. 写一份交付说明和缺陷报告，演示一个缺陷如何被测试发现。

允许查官方文档；关键实现和结论必须自己能解释。复用框架样例时标出来源，区分已有内容与自己新增内容。

## 3. 达到什么程度

完成上述交付后，你应能承担有明确范围的初级接口自动化任务：设计并维护测试、定位常见失败、核对数据、运行回归并提交证据。是否满足具体岗位，还需对照该岗位业务、技术栈和面试要求。

本教程不自动等同于：生产项目经验、熟练 MySQL 运维、Linux 系统管理、大规模分布式压测、性能调优、UI/移动自动化、完整安全测试。没有做过的项目不要从目录或样例中推断为自己已经掌握。

## 4. 整理一个面试作品包

建议包含 README、契约与用例表、标明个人贡献的代码、SQL 作业、Linux 排障记录、CI 链接、JMeter 原始结果与报告、缺陷报告。报告引用明确版本和日期；密码、token、公司内部地址不放进公开仓库。

最后打开 [简历与面试](RESUME_INTERVIEW.md)，只把自己通过验收、能现场演示的部分写进去。
